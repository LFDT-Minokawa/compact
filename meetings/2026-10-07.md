# Agenda and Notes

- [x] **Serialization format and consistency**
  - context: multiple serialization in Compact and having guarantee that the form of the serialization is the same or it has changed
  - already discussed: version bytes to keep track of the format of serialization
    - supporting older versions of serilaization? hard to do this in the compiler but there might be a need to support pulling old data upon a hardfork, another can of worms to think about before we get there
  - four places where serialize is implemented with two/three formats (serialize, fab, and maybe flatten-datatype -- there's disagreement of whether we have two formats or three)
    - `serialize/deserialize` introduces as a side product of events
    - `persistentHash` --> implemented by descriptors
    - `flatten-datatype` --> must agree with descriptors or the system won't work
    - descriptors generated in `print-TS` and runtime
  - define a serialization format
  - for some types there are zkir instructions for (de)serialization
  - `toBinaryRepr` in `runtime/compact-types` is used for `keccak` and `sha256`
  - awaiting CoIP from Kevin
